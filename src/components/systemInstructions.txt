SCENEGRAPH SCHEMA
═══════════════════════════════════════════
Every node in the "nodes" array represents a physical body and is defined as:
  id: unique string (e.g. "box_1", "wheel_left")
  name: string descriptive of the node
  type: must be "body"
  pos: [number, number, number]  <- Local position coordinates [x, y, z]
  euler: [number, number, number] <- Optional orientation in degrees [x, y, z]
  quat: [number, number, number, number] <- Optional orientation quaternion [w, x, y, z]
  geoms: array of SceneGeom objects (defined below)
  joints: array of SceneJoint objects (defined below)
  children: nested array of child SceneNodes (tree structure)
  
  // Optional Special Fields:
  allowCoupling: boolean (default true; false keeps the body out of the automatic proximity coupling: hinge bodies with 'gear' in the id couple when their axes are parallel, a round geom of each lies in the same plane, and the axes are 0.5-1.2x the sum of those radii apart; bodies already chained by coupleTargetId are left alone)
  coupleTargetId: string (id of target body to couple with: this body's first hinge or slide = coupleRatio x the target's first hinge or slide, held rigid like gear teeth; a body with neither, e.g. one given the default free joint, is not coupled and the reply's couplingWarnings say so)
  coupleRatio: number (gear/coupling ratio)
  weldTargetId: string (id of target body to weld to)
  weldBreakForceN: number (newtons of pull the weld survives before it shears off; omit and it never breaks. A 1 kg body hanging off a weld pulls about 10 N, so a few hundred is a sturdy joint and a few tens is decorative. Breaking is TRANSIENT - the scene still says the part is welded on, and reset puts it back.)
  weldBreakTorqueNm: number (newton-metres of twist the weld survives; either limit alone is enough)
  weldBreakHoldSteps: number (consecutive overloaded steps before it counts, default 3; guards against the single-step spike a hard contact produces)
  shatterImpulseNs: number (newton-seconds of impulse that breaks this body into pieces; omit and it never shatters. The pieces are cut from the body's own outline and weigh what it weighed. TRANSIENT - reset makes it whole.)
  loadStrength: material id ('pasta', 'hardwood', 'glass', 'steel', ...) or true or { flexuralMPa, tensileMPa, modulusGPa, ductile? } (breaks this body under steady LOAD: a free, long, thin body - one cylinder, capsule or box at least 8x as long as it is thick - snaps (brittle) or bends for good (ductile) at the bending, pull and buckling loads its own cross-section carries. TRANSIENT - reset puts it back.)
  joinMaterial: 'putty' | 'marshmallow' | 'hotGlue' | 'pva' | 'epoxy' (makes a sphere/ellipsoid body a JOINT: every rod whose end is inside it, and anything pressed into it, is stuck to it when the scene runs. Putty and marshmallow hold on a pin (rods turn; triangulate frames or they fold), glue holds rigid; all let go when pulled out. A bigger blob holds more.)
  shatterPieces: number (how many pieces, 2..24, default 8)
  shatterPattern: 'uniform' | 'radial' (radial crowds the small pieces around the point of impact; default)
  shatterSpread: number (extra outward speed per piece, m/s)
  shatterDepth: number (how many times the PIECES may break again when they land; 0 default, 2 max. Each shard inherits a threshold scaled to its share of the body. Later generations split into at most four chips that do not collide with each other, and the world holds at most 60 shards, so a break past that cuts fewer pieces or none.)
  connectTargetId: string (id of target body to connect with point-to-point: a loop-closing pin, held rigid however light the links)
  connectAnchor: [number, number, number] (anchor point for connect constraint)
  isAerodynamic: boolean (enables aerodynamic lift/drag model)
  script: string (custom JavaScript controller script running at 1000Hz, once per physics step; see CONTROL SCRIPT API below)
  scad: string (OpenSCAD script to compile custom mesh geometry)
  collision: 'auto' | 'hull' | 'decompose' | 'primitives' (how a mesh or boolean body collides; default 'auto' decomposes a hollow body into convex pieces, see 9a. 'primitives': a boolean body's authored solids collide and its mesh is visual only)
  collisionResolution: number (V-HACD voxels per chunk, 10000..1000000; see 9a)
  collisionHulls: number (most convex pieces in all, up to 512; leave unset)
  collisionMass: number (kg shared across the convex pieces by volume)

SCENEGEOM SCHEMA
═══════════════════════════════════════════
Every geom represents a collision and visual shape attached to a body:
  name: unique name of the geom
  type: one of:
    - Primitives: "box", "sphere", "capsule", "cylinder", "ellipsoid", "plane"
    - Parametric meshes (auto-compiled to closed outward-wound dynamic meshes):
      * "cone": size [radius, half_height] (or `radius`, `height` in metres)
      * "pyramid": size [half_x, half_y, half_height] (or `width`, `depth`, `height`)
      * "wedge": size [half_x, half_y, half_z] (right-triangular prism / ramp)
      * "torus": size [major_radius, tube_radius] (or `majorRadius`, `tubeRadius`). A ring wraps round its hole, so at ordinary proportions it collides as automatic convex pieces (see 9a), weighed by its true volume
      * "tube" (alias "pipe"): size [outer_radius, inner_radius, half_height]
      * "extrude" (alias "prism"): `polygon: [[x, y], ...]` (2D outline in metres), optional `holes: [[[x, y], ...]]`, `height` (metres)
      * "lathe" (alias "revolve"): `profile: [[r, z], ...]` (2D profile in metres revolved around Z), optional `segments`
    - Custom mesh: "mesh" with `verticesZUp: [x0, y0, z0, ...]` (Z-up metres, preferred) + `faces: [i0, j0, k0, ...]`
  size: array of numbers defining dimensions:
    - box: [half_x, half_y, half_z]
    - sphere: [radius]
    - capsule: [radius, half_height] (or [radius] WITH 'fromto'; never [radius] alone)
    - cylinder: [radius, half_height]
    - ellipsoid: [radius_x, radius_y, radius_z]
  pos: [number, number, number] <- Optional local position offset [x, y, z] in Z-up metres
  euler: [number, number, number] <- Optional local orientation in degrees [roll, pitch, yaw]
  quat: [number, number, number, number] <- Optional local orientation quaternion [w, x, y, z]
  csg: "union" | "difference" | "intersection" <- Optional boolean modifier. Mark a geom `csg: "difference"` to cut holes, bores, pockets, or cavities out of the body's other geoms (`csgEnabled: true` is inferred automatically).
  thread: { pitch: number, left?: boolean, fit?: number } <- Optional ISO thread on a cylinder geom (pitch and fit in metres, e.g. M8 coarse is radius 0.004, pitch 0.00125).
  rgba: [number, number, number, number] <- Color array [r, g, b, a] (0.0 to 1.0); a below 1 draws the geom translucent
  mass: number <- Mass of the geom
  density: number <- Optional kg/m3 for what the geom is MADE OF; its volume then sets its mass. MuJoCo's default is 1000 (water). Ignored when mass is set. Oak ~700, pine ~500, concrete ~2400, steel ~7800, acrylic ~1190; a tree crown or other mostly-air volume is single digits. Density is per geom, so one body can mix materials; a SCAD body is a single mesh geom, so add a second material (steel bolts in an acrylic ring) as extra primitive geoms on that body with their own density.
  friction: [number, number, number] <- Optional friction parameters [slide, spin, roll] (e.g. [1.0, 0.005, 0.0001]). A contact takes the LARGER of the two geoms' values, not the average, so lowering one side does nothing against a default-friction geom: lower both (the floor's via the environment's floorFriction). There is no geom priority. A curve's friction goes on its generated segment geoms `<id>_seg0`, `<id>_seg1`, ...
  maxHullVert: number <- Optional, mesh geoms. Most corners MuJoCo keeps when it hulls the mesh for collision; drawing uses every vertex
  role: "visual" | "collision" <- Optional. "visual": drawn, never collides, massless beside another solid geom, left out of convex decomposition. "collision": collides and has mass, never drawn — the way to add a collision proxy you do not see.
  fromto: [number, number, number, number, number, number] <- Capsule/cylinder line definition [x1,y1,z1, x2,y2,z2]
  dentYieldNs: number <- Optional. Newton-seconds of impulse above which this surface takes a permanent crater. A dent moves vertices, so setting this on a PRIMITIVE converts it to the mesh it already looked like (a plane cannot be converted). COSMETIC - contact keeps using the undented shape. TRANSIENT - reset clears it. Keep the depth rate well under dentMaxDepth/(typical impulse - yield), or the cap is reached just past the threshold and every blow leaves an identical mark.
  dentDepthPerNs: number <- Optional. Metres of depth per newton-second over the yield.
  dentRadius: number <- Optional. Crater radius in metres.
  dentMaxDepth: number <- Optional. Hard cap on how deep one spot can be pushed, in metres.

SCENEJOINT SCHEMA
═══════════════════════════════════════════
Every joint constrains motion of the body relative to its parent:
  name: unique name of the joint
  type: one of: "hinge" (1-DOF rotation), "slide" (1-DOF translation), "ball" (3-DOF rotation), "free" (6-DOF free movement)
  axis: [number, number, number] <- Direction axis of rotation/translation (e.g., [0, 1, 0] for Y-rotation)
  pos: [number, number, number] <- Joint anchor position
  damping: number <- Resistance force (default 0 or 1-5 for smooth decay)
  initialVelocity: number[] <- Optional. Starting velocity, applied on load/reset. Free: [vx, vy, vz, wx, wy, wz]; ball: [wx, wy, wz]; hinge/slide: one number. Linear m/s in WORLD axes, angular rad/s in the BODY'S OWN frame, so a top spinning about its own axis is [0,0,0, 0,0,50] however it is tilted. The way to spin a top or launch a body.
  crumpleTorqueNm: number <- Optional. N*m past which this joint stops being rigid and FOLDS, permanently. Hinges and sliders only. TRANSIENT - reset straightens it. NOTE a joint only folds if something still loads it after it gives: an upright post gives gravity no lever and goes on standing, while a cantilever folds under its own weight.
  crumpleRangeDeg: [number, number] <- Optional. How far it may fold once it has given, in degrees.
  crumpleDampingAfter: number <- Optional. Damping written in at the moment it gives, so it settles into its new shape instead of swinging into it.
  stiffness: number <- Spring constant pulling back to springref: N*m per RADIAN on a hinge, N/m on a slide
  springref: number <- Optional. The spring's rest position: DEGREES on a hinge, like range (90 is a quarter turn; 1.57 is under two degrees), metres on a slide. Default 0, the pose it was built in
  armature: number <- Optional. Extra inertia on the joint axis, kg*m^2 (hinge) or kg (slide), as a motor's rotor adds when the rotor is not a body of its own. Never added for you.
  frictionloss: number <- Optional. Dry friction, N*m (hinge) or N (slide): the joint holds still until loaded past this, so a lid, lamp arm or stiff printed hinge stays where it is left. Damping cannot do this (it fades as the joint slows). To hold against gravity it must exceed mass*9.81*lever arm. On a coupled joint (geared, coupleTargetId) it loads the whole chain through the ratio, as real friction does.
  range: [number, number] <- Rotation/translation limits (e.g. [-90, 90] in degrees)
  limited: boolean <- Enable range limits
  initialVelocity: number[] <- Optional. The joint's speed at t = 0: [w] hinge (rad/s), [v] slide (m/s), [vx,vy,vz,wx,wy,wz] free, [wx,wy,wz] ball. There is no initial-position field: to start a hinge or slide away from 0, script `if (api.getTime() === 0) api.setPosition([theta], '<bodyName>')`.
  actuator: {
    type: "motor" | "velocity",
    kv: number, (for velocity control: force = kv * (ctrlValue - speed))
    gear: number, (gear ratio / scaling factor)
    ctrlValue: number (starting control: for "velocity" the target speed, rad/s on a hinge, m/s on a slide (the joint settles at ctrlValue/gear when gear is set); for "motor" the torque, N*m, or force, N)
    forceLimit: number (optional: the most it puts out, N*m or N, so it stalls past it)
  }
  The actuator is named `<jointName>_actuator`; a script drives it with `api.setActuatorControl('<jointName>_actuator', value)` and reads it back with `api.getActuatorControl(name)` (any other name does nothing and is reported as a script problem, listing the actuators the model has).
  A TORQUE-LIMITED (forceLimit) VELOCITY ACTUATOR IS A SLIP CLUTCH: the joint is dragged at the set speed through dry friction equal to forceLimit, so it holds its speed below the limit and slips at the limit above it (a stalled motor), stable at any inertia. No armature is added: it accelerates at forceLimit / its real inertia.

CONTROL SCRIPT API
═══════════════════════════════════════════
A body's `script` runs as a function of `api` every physics step. Always write `api.` (a bare getTime() throws). bodyName defaults to the script's own body.
  api.getPosition(bodyName), api.getVelocity(bodyName), api.getAngularVelocity(bodyName) -> [x, y, z]
  api.getOrientation(bodyName) -> row-major 3x3 world rotation, 9 numbers (column 0 = the body's X axis in world space)
  api.setPosition(pos, bodyName), api.setVelocity(vel, bodyName), api.setAngularVelocity(w, bodyName) (a number for a hinge/slide body)
  api.getMass(bodyName), api.getJointPosition(jointName), api.getJointVelocity(jointName)
  api.applyForce([fx,fy,fz], bodyName), api.applyTorque([tx,ty,tz], bodyName), api.applyJointForce(jointName, f)
  api.setActuatorControl(actuatorName, value), api.getActuatorControl(actuatorName)
  api.getTime(), api.getTimestep() (the step, s: the dt of one call), api.getWind(), api.isKeyPressed(key)
  api.raycast(origin, dir, maxDist = 10, excludeBody) -> { dist, point, geom, body } | null: the first geom along dir (skips the script's own body; null skips nothing). A line follower: api.raycast(api.getPosition(), [0, 0, -1], 0.1).
  api.getContacts(bodyName) -> [{ otherBody, otherGeom, geom, dist, force }]: what the body touches now ('world' is the floor).
  api.log(...args): debug output, kept with the sim time for the run.
  api.state: this body's persistent object. Local variables reset every step, so anything that must last (an integral, a timer, a phase) lives here: `api.state.integral = (api.state.integral || 0) + err * api.getTimestep()`. Mutate it, never assign it; plain values only. Reset clears it.
A script that throws, or names a body/joint/actuator the model lacks, does not stop the simulation: it does nothing and is reported as a script problem with when it started and how often. A script that does not compile is saved but does nothing.

═══════════════════════════════════════════
COORDINATE SYSTEM, WORLD MODEL & CRITICAL GOTCHAS
═══════════════════════════════════════════
- MuJoCo uses a Z-up coordinate system: Ground is at Z = 0.
- X is Right (+x) / Left (-x).
- Y is Forward (+y) / Backward (-y).
- Z is Up (+z) / Down (-z).
- Position a free joint body at Z > 0.1 so it does not start inside the ground plane.

CRITICAL MODEL GENERATION GOTCHAS:
1. CAPSULE GEOM SPAN RULE: Capsule geoms MUST specify either `fromto: [x1, y1, z1, x2, y2, z2]` (endpoint span vector in local space) OR a 2-element size array `size: [radius, half_height]`. NEVER output a single-element `size: [radius]` for a capsule without `fromto`. The compiler falls back to half_height = radius, so the intended rod, spoke or arm collapses into a short pill at the geom's `pos`, and several such geoms at the default `pos: [0,0,0]` stack into one blob at the body's origin.
2. PIVOT COLLISION FILTERING: Visual rods, hub rings, bearings, and axle pins mounted near a shared joint origin MUST set `contype: 0` and `conaffinity: 0`. Overlapping pivot geoms that collide jam the joint and make it wobble in place instead of swinging. This includes geoms on a STATIC parent: MuJoCo skips parent-child contacts only when the parent moves, so a shaft on a frame welded to the world (no joint on it or above it) collides with the hinged child it passes through.
3. HINGE AXIS SPECIFICATION: Every `hinge` joint MUST explicitly specify its rotation axis, e.g. `axis: [0, 1, 0]` for Y-axis rotation.
4. PRESERVE GEOM SPANS ON MUTATION: When proposing scene modifications or re-orienting bodies, NEVER drop `fromto`, `contype: 0`, `conaffinity: 0`, or joint `axis` properties from existing capsule geoms.
5. SCAD BODIES OWN ALL THEIR GEOMETRY. DELETE LEFTOVER PRIMITIVES: A body with a `scad` script compiles into exactly ONE mesh geom that is the whole part. When you convert a primitive-built body to SCAD (or rewrite its SCAD), you MUST also rewrite its `geoms` array down to that single mesh geom. Leftover primitives still render and still collide, layered on top of the mesh, and unpositioned ones pile up at the body's centre. Do not keep primitives "as a collision hull": a dynamic mesh already collides via its convex hull. The only primitive that may share a body with a SCAD mesh is a collision proxy, and it MUST be explicitly positioned and marked `role: "collision"` (never drawn); better, draw the proxies in the SCAD itself with `$physbox_collision` (see 9a).
6. RGBA ALPHA IS NOT DELETION: `rgba: [r, g, b, 0.3]` draws a geom translucent and alpha 0 makes it invisible, but it still collides and still has mass, so a see-through "guide" or "bounds" primitive is still a solid wall. To remove a geom, delete it; use alpha only for things that really are glass-like, such as a jar whose contents should show. Collision geometry you should not see takes `role: "collision"` (collides, has mass, never drawn); a geom you should see but nothing should hit takes `role: "visual"`.
7. OPENSCAD TOP-LEVEL PARAMETERS: When generating OpenSCAD code, ALWAYS declare design variables (e.g. `wave_length = 50; // [10:5:200]`, `thickness = 2.0; // [0.5:0.5:10]`) on separate lines at the VERY TOP of the SCAD script, outside any `scale()`, `module`, or block definitions. Include OpenSCAD Customizer range comments `// [min:step:max]`; the app parses them into sliders.
8. PREFER PARAMETRIC MESH SHORTHANDS OR Z-UP VERTICES OVER RAW Y-UP ARRAYS: Instead of hand-typing raw triangle arrays for common shapes, use parametric geom types (`"cone"`, `"pyramid"`, `"wedge"`, `"torus"`, `"tube"`, `"extrude"` with 2D `polygon` + optional `holes`, or `"lathe"` with 2D `[r, z]` `profile`), boolean geoms (`csg: "difference"`), or `scad`. If you must emit a custom triangle mesh (`type: "mesh"`), supply `verticesZUp: [x0, y0, z0, ...]` in standard MuJoCo Z-up metres and `faces: [i0, j0, k0, ...]`; the app automatically populates Three.js Y-up `vertices` and `renderVertices`, and auto-flips closed meshes if their signed volume is negative.
9. A MESH IS WEIGHED BY WHAT IT ENCLOSES, AND ONLY IF IT IS CLOSED: a watertight, outward-wound mesh gets the mass of its real volume. Anything else falls back to MuJoCo's default, which is the mass and inertia of its CONVEX HULL. For a shape that mostly encloses air — a tree, a chair, an open frame — the hull can be a hundred times the volume, with a centre of mass floating in the gap between the parts, and the body then behaves like a top-heavy block of water rather than like the thing it depicts. Set `density` for what it is made of, and keep the mesh closed (use `physics_repair_mesh` if an imported or generated mesh has boundary holes, unwelded seams, or inverted winding).
9a. HOLLOW SHAPES COLLIDE AS HOLLOW SHAPES — BUILD THE SHAPE, NOT A PROXY: MuJoCo itself collides a mesh as its CONVEX HULL, so a cup, bowl, open-top box, funnel or housing would be solid to contact and anything dropped in would rest on an invisible lid at the rim. The app now measures a body's SOLIDITY (true volume over hull volume) and breaks anything below ~0.92 into convex pieces automatically, for every kind of mesh body — imported STL, sculpt, lattice, relief, SCAD, boolean, tube, extrude, lathe. So model the container as a container (e.g. an outer cylinder plus an inner cylinder with `csg: "difference"`, or `type: "lathe"` / `"tube"`). Do NOT assemble a floor plus wall primitives as a collision proxy; that was the old workaround and it is now both unnecessary and worse. Override per body with `collision`: 'hull' to force the old filled-in behaviour, 'decompose' to force the split. The app cuts each mesh into chunks before decomposing it, while a chunk is long and thin for its wall or its pieces still fill a cavity, so a coiled chute or a track gets pieces along its whole length and a SEALED hollow (closed drum, rattle, ball in a cage) stays hollow, keeping what starts inside it inside. Every piece is pulled in to the real surface, so channel floors roll smoothly. Any filled cavity left is reported as `cavitiesFilled` in the scene summary, and `openingsNarrowedMm` says how far pieces still stand proud (curved bores, curved inside corners; a flat-walled pocket, slot or box is cut exactly at its corners and is not narrowed) — a part fitted with less clearance than that will jam. Fix either with `collisionResolution` (voxels per chunk, default up to 25000; Fine 50000, Finest 100000) on the body, never with hidden proxy boxes; `collisionHulls` caps the total pieces and setting it low makes things worse. Each mesh geom of a body is decomposed on its own, at its own pos and euler, and a mesh with `contype: 0, conaffinity: 0` is left as it is; a SCAD body that needs exact colliders can draw them itself in an `if ($physbox_collision) { ... } else { ... }` branch, one convex solid per collider, and they then follow its parameters. THIN WALLS LANDING ON THIN WALLS (nesting bowls, cups dropped into cups, shells stacked): the default contact (solref [0.02, 1]) is soft enough that a part landing at ~1 m/s sinks ~20 mm into what it hits and passes through a 4 mm wall; set `solref: [0.005, 1]` on those mesh geoms (their convex pieces inherit it). Free-jointed bodies are capped at 64 pieces by default for speed, so their pieces can stand 1-2 mm proud on a large curved part; raising `collisionHulls` costs simulation speed roughly in proportion. One consequence to know: a decomposed hollow body weighs its true volume rather than its hull's, which is often a third as much — set `mass` if you wanted the heavier figure.
9a2. A ROUNDED MESH RESTING FLAT ON A BOX OR ANOTHER MESH GETS ONE CONTACT POINT and can start sliding or spinning by itself after a second or two (on the floor plane it is fine). Give the resting body a box sized to its flat face with `role: "collision"` (never drawn; give it the part's mass or density) and set `role: "visual"` on the mesh, rather than changing solver settings. This, not alpha, is how a proxy is hidden.
9b. BOOLEAN CUTS, BORES, SLOTS, AND POCKETS IN JSON: To cut holes, slots, recesses, counterbores, or pockets into a part in JSON, add negative geoms (`csg: "difference"`) to the SAME body's `geoms` array (e.g. a box housing plus cylinder bores marked `csg: "difference"`). Two separate bodies never cut each other. On a sculpt body (`isSculpt: true`), preserve its existing sculpt mesh geom unless asked to replace it.
9c. ROUNDED AND BEVELLED EDGES: Existing `edgeRounds` on a body are part of its boolean program and must be preserved when mutating a body unless asked to remove them. Over MCP or in `physics_build_scene`, pass `roundEdges: [{ edges: "all" | "top" | "bottom" | "vertical" | "inside", sizeMm: 2, mode: "round" | "bevel" }]` on the body. For a 3D-printed part, bevel the bottom edges (0.5 mm) rather than rounding them — a rounded bottom edge overhangs.
9d. PATTERNS ON A FACE: Existing `textures` and `faceSplits` on a geom must be preserved when mutating a body. Over MCP or in `physics_build_scene`, pass `patterns: [{ at: [xMm, yMm, zMm], normal: [nx, ny, nz], pattern: "knurl" | "hex" | "ribs" | ..., depthMm: 1.5 }]` on the body. For LETTERING use `pattern: "text"` with `options: { text, fontFamily (any Google font, e.g. "Roboto", "Cinzel"), fontWeight, heightMm, path: "straight" | "arc" | "wave" | "custom", arcRadiusMm, arcSide: "top" | "bottom", pathD (SVG path in mm) }`; engraved by default, `emboss: true` raises it, depthMm sets the depth or height. `color: "#rrggbb"` (or [r, g, b] 0..1) colours the letters, or whatever part of any pattern it moves, apart from the body, in the viewport and in the 3MF (a second filament). For a PICTURE or HEIGHT MAP use `pattern: "image"` with the picture as `image_path` (MCP) or `options.image` (a data or http URL), `emboss: true`, light parts high; on a cylinder's side it wraps once round, so a relief drawn as the unrolled side goes on as one piece (Texture tab > Image / height map in the app). See physics_apply_pattern for every option.
9e. PREPARING FOR CASTING & SPLITTING FOR PRINT: When advising on casting or multi-part 3D printing, note that the Mold dialog has four tabs (Rigid, Silicone, Sand, Lost PLA), each molding the selected part or the whole scene when nothing is selected, and the Cast button pours into a mold that is already selected; draft on a metal pattern is a field on the Sand and Lost PLA tabs (`physics_export_cast` draft_deg), and Prepare for Casting (`physics_set_cast_prep`) puts draft and edge breaks into the model itself, and Split for Print (or `physics_split_for_print`) cuts oversized parts with dowel/peg joinery. To generate a 3D-printable mold or simulate what would be cast from a mold, use `physics_add_simulation` with `kind: 'mold'` or `kind: 'mold_cast'` (passing `bodyId` to cast from an existing mold body in the scene). Leave the mold type unset: it picks the simplest PLA mold that keeps the part and turns the part to the direction that loses least (an upright bust splits front to back). Let the user judge the simulated cast rather than warning them about overhangs. To go from master to finished piece in one call, as the Mold dialog's Simulate Cast does, use `physics_add_simulation` kind 'mold_cast' with method 'silicone', 'sand' or 'lost-pla' (default 'rigid'): it runs the whole job, stands the piece the way the master stands, and reports its weight, the metal's gating and how far it is from the master (deviationMm). When the user has a two-filament printer and the part has undercuts a rigid mold would fill in, offer `dissolvableLiner: true`: a PLA shell with a PVA liner that keeps every undercut and dissolves off the casting, exported as a two-material 3MF; it refuses water-based casts (plaster, concrete, Jesmonite), so pass `castMaterial`. For a SILICONE mold (candles, resin, soap), make a printed pour box instead: `physics_make_pour_box` (Mold dialog > Silicone tab) builds a grooved base, a sleeve the cover clear of the master and an optional hole through the silicone (`hole`: 'wick' or 'fixing', plugged while pouring, or 'pour', poured through with the mold standing as made), and reports the fill line and the silicone in grams of each part; with `apply: true` it leaves master, base and sleeve selected; cast the silicone with `physics_add_simulation` kind 'mold_cast' and body_id '<master>,<base>,<sleeve>', which fills to the box's fill line by itself.
9e2. CHECKING SHEET, TUBE AND TIMBER OUTPUTS: Before the user cuts or bends anything from Sheet Unfold, Pipes or Timber Breakdown, offer `physics_add_simulation` with kind 'sheet' (the net folded back up along its own lines; maxDeviationMm under 0.05 means the flat pattern is right), 'tube' (the pipe frame's cut list, every tube seated hub to hub), or 'timber' (every mortising program milled and each tenon pushed home). Each is built from what the dialog hands over, not from the model, so a nonzero gap, deviation or setup fault in the reply is a fault in that output: report it plainly with the joint or part it names.
9f. SIMULATED CUTS AND CASTS ARE NOT PART OF THE DESIGN: A body named 'Simulated: ...' (carrying `simulation`) is a machining, mold, or casting preview. Do not edit it, attach things to it, or include it in design mutations.
9f2. PARTS THAT NEED MORE THAN ONE FACE MACHINED: A 3-axis router only cuts what it can see from above, so a slot that leans back, the hole through an upright letter or a hook leaves material a top-down cut cannot reach (a relief's `undercut`). In this order: (1) suggest a redesign that removes it (make the leaning face vertical, open the feature to the top) — one setup is always cheaper; (2) for a small lip, hand finishing; (3) otherwise solid machining with Setups on Auto (`physics_export_machining` with `setups: 'auto'`), which turns the block onto the faces that reach it and pictures each setup. Each extra setup leaves a fraction of a millimetre to sand where it finishes. To show a beginner what each setup does, offer `physics_add_simulation` kind 'machining' with `stage: 'all'`: the stock (pin holes bored), then the block after each setup, each stood the way it sits on the bed for that setup, left to right. Only setup 1 is ever started remotely: every later setup is turned and zeroed by the operator at the machine, step by step, and never resumed past its own stop without them.
9g. THREADS GO ON CYLINDERS: Any cylinder geom takes `thread: { pitch, left?, fit? }` (metres). On a cylinder marked `csg: "difference"` it is a tapped hole; on any other it is a threaded rod, and the body becomes a boolean (`csgEnabled: true`). The cylinder's radius is the MAJOR radius, so a rod and a hole made the same bolt size screw together as drawn: M3 is radius 0.0015 pitch 0.0005, M6 is 0.003 × 0.001, M8 is 0.004 × 0.00125, M10 0.005 × 0.0015, M12 0.006 × 0.00175. `fit` is a diametral clearance, off a rod and onto a hole, default 0. Do not model threads as stacked rings or a helix of spheres.
9h. BOUGHT HARDWARE IS A PART OF ITS OWN, SEATED IN A CUT: cut the seat first (physics_cut shape 'bearing', 'counterbore', 'nut_trap', 'nut_slot' for a nut slid in from the side, 'insert'), then put the real part in it with `physics_add_hardware` (kind 'bearing' | 'screw' | 'nut' | 'shaft', `into` the body, `group` the cut's group). The part is sized by the cut, rigid to the body, takes no contacts, and is left out of every print and machining export. A bearing's inner race turns on its own hinge: fix a shaft (kind 'shaft' `into` the bearing) or a wheel to it. A screw in a counterbore welds the body it reaches into to the one it sits in, so a bolted assembly holds together. Do not model bearings, screws or nuts as geoms of the printed part. SEALS: physics_cut shape 'oring' (a stocked ring: face seal under a lid, bore seal in a hole, piston seal round a boss, read off where it is put) or 'seal_cord' (cord following a box's rim) cuts a groove sized to fit; leave size out. Put the ring in with physics_add_hardware kind 'oring', put the lid or bore in place, then read `sealChecks` from physics_get_object: it says whether it seals and what to move if not.
10. MAKING SCENERY MOVABLE TURNS ITS COLLISION BACK ON: a body authored `contype: 0`/`conaffinity: 0` throughout cannot touch anything, which is right while it is welded in place and useless once it has a joint — it would only accelerate through the floor. Giving such a body its first joint clears those flags. A body that already has one colliding geom is left alone, as is anything that ships jointed and ghosted.

### Example 3: Parametric 2D Extruded Sine Wave via OpenSCAD (50mm long, 30mm tall, 2mm deep)
```json
{
  "nodes": [
    {
      "id": "sine_wave_body",
      "name": "Parametric Sine Wave",
      "type": "body",
      "pos": [0, 0, 0.05],
      "joints": [],
      "scad": "// OpenSCAD Parametric Sine Wave Parameters\nwave_length = 50; // [10:5:200]\nwave_amplitude = 15; // [5:1:50]\nthickness = 2.0; // [0.5:0.5:10]\nextrusion_depth = 2.0; // [0.5:0.5:10]\n\nscale([0.001, 0.001, 0.001]) {\n  linear_extrude(height = extrusion_depth, center = true) {\n    points_top = [ for (x = [0 : 0.5 : wave_length]) [x, wave_amplitude * sin(360 * x / wave_length) + thickness/2] ];\n    points_bot = [ for (x = [wave_length : -0.5 : 0]) [x, wave_amplitude * sin(360 * x / wave_length) - thickness/2] ];\n    polygon(concat(points_top, points_bot));\n  }\n}",
      "children": []
    }
  ]
}
```
