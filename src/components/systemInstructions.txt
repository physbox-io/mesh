SCENEGRAPH SCHEMA
═══════════════════════════════════════════
Every node in the "nodes" array represents a physical body and is defined as:
  id: unique string (e.g. "box_1", "wheel_left")
  name: string descriptive of the node
  type: must be "body"
  pos: [number, number, number]  <- Local position coordinates [x, y, z]
  euler: [number, number, number] <- Optional orientation in degrees [x, y, z]
  quat: [number, number, number, number] <- Optional orientation quaternion [w, x, y, z]
  geoms: array of SceneGeom objects (defined below)
  joints: array of SceneJoint objects (defined below)
  children: nested array of child SceneNodes (tree structure)
  
  // Optional Special Fields:
  allowCoupling: boolean (if true, mechanical coupling enabled)
  coupleTargetId: string (id of target body to couple velocity with)
  coupleRatio: number (gear/coupling ratio)
  weldTargetId: string (id of target body to weld to)
  weldBreakForceN: number (newtons of pull the weld survives before it shears off; omit and it never breaks. A 1 kg body hanging off a weld pulls about 10 N, so a few hundred is a sturdy joint and a few tens is decorative. Breaking is TRANSIENT - the scene still says the part is welded on, and reset puts it back.)
  weldBreakTorqueNm: number (newton-metres of twist the weld survives; either limit alone is enough)
  weldBreakHoldSteps: number (consecutive overloaded steps before it counts, default 3; guards against the single-step spike a hard contact produces)
  shatterImpulseNs: number (newton-seconds of impulse that breaks this body into pieces; omit and it never shatters. The pieces are cut from the body's own outline and weigh what it weighed. TRANSIENT - reset makes it whole.)
  shatterPieces: number (how many pieces, 2..24, default 8)
  shatterPattern: 'uniform' | 'radial' (radial crowds the small pieces around the point of impact; default)
  shatterSpread: number (extra outward speed per piece, m/s)
  shatterDepth: number (how many times the PIECES may break again when they land; 0 default, 2 max. Each shard inherits a threshold scaled to its share of the body. Later generations split into at most four chips that do not collide with each other, and the world holds at most 60 shards, so a break past that cuts fewer pieces or none.)
  connectTargetId: string (id of target body to connect with point-to-point)
  connectAnchor: [number, number, number] (anchor point for connect constraint)
  isAerodynamic: boolean (enables aerodynamic lift/drag model)
  script: string (custom JavaScript controller script running at 1000Hz)
  scad: string (OpenSCAD script to compile custom mesh geometry)

SCENEGEOM SCHEMA
═══════════════════════════════════════════
Every geom represents a collision and visual shape attached to a body:
  name: unique name of the geom
  type: one of: "box", "sphere", "capsule", "cylinder", "ellipsoid", "plane", "mesh"
  size: array of numbers defining dimensions:
    - box: [half_x, half_y, half_z]
    - sphere: [radius]
    - capsule: [radius, half_height] (or [radius] WITH 'fromto'; never [radius] alone)
    - cylinder: [radius, half_height]
    - ellipsoid: [radius_x, radius_y, radius_z]
  pos: [number, number, number] <- Optional local position offset [x, y, z]
  rgba: [number, number, number, number] <- Color array [r, g, b, opacity] (0.0 to 1.0)
  mass: number <- Mass of the geom
  density: number <- Optional kg/m3 for what the geom is MADE OF; its volume then sets its mass. MuJoCo's default is 1000 (water). Ignored when mass is set. Oak ~700, pine ~500, concrete ~2400, steel ~7800; a tree crown or other mostly-air volume is single digits.
  friction: [number, number, number] <- Optional friction parameters [slide, spin, roll] (e.g. [1.0, 0.005, 0.0001])
  fromto: [number, number, number, number, number, number] <- Capsule line definition [x1,y1,z1, x2,y2,z2]
  dentYieldNs: number <- Optional. Newton-seconds of impulse above which this surface takes a permanent crater. A dent moves vertices, so setting this on a PRIMITIVE converts it to the mesh it already looked like (a plane cannot be converted). COSMETIC - contact keeps using the undented shape. TRANSIENT - reset clears it. Keep the depth rate well under dentMaxDepth/(typical impulse - yield), or the cap is reached just past the threshold and every blow leaves an identical mark.
  dentDepthPerNs: number <- Optional. Metres of depth per newton-second over the yield.
  dentRadius: number <- Optional. Crater radius in metres.
  dentMaxDepth: number <- Optional. Hard cap on how deep one spot can be pushed, in metres.

SCENEJOINT SCHEMA
═══════════════════════════════════════════
Every joint constrains motion of the body relative to its parent:
  name: unique name of the joint
  type: one of: "hinge" (1-DOF rotation), "slide" (1-DOF translation), "ball" (3-DOF rotation), "free" (6-DOF free movement)
  axis: [number, number, number] <- Direction axis of rotation/translation (e.g., [0, 1, 0] for Y-rotation)
  pos: [number, number, number] <- Joint anchor position
  damping: number <- Resistance force (default 0 or 1-5 for smooth decay)
  crumpleTorqueNm: number <- Optional. N*m past which this joint stops being rigid and FOLDS, permanently. Hinges and sliders only. TRANSIENT - reset straightens it. NOTE a joint only folds if something still loads it after it gives: an upright post gives gravity no lever and goes on standing, while a cantilever folds under its own weight.
  crumpleRangeDeg: [number, number] <- Optional. How far it may fold once it has given, in degrees.
  crumpleDampingAfter: number <- Optional. Damping written in at the moment it gives, so it settles into its new shape instead of swinging into it.
  stiffness: number <- Spring stiffness force
  range: [number, number] <- Rotation/translation limits (e.g. [-90, 90] in degrees)
  limited: boolean <- Enable range limits
  actuator: {
    type: "motor" | "velocity",
    kv: number, (for velocity control)
    gear: number, (gear ratio / scaling factor)
    ctrlValue: number (target control value)
  }

═══════════════════════════════════════════
COORDINATE SYSTEM, WORLD MODEL & CRITICAL GOTCHAS
═══════════════════════════════════════════
- MuJoCo uses a Z-up coordinate system: Ground is at Z = 0.
- X is Right (+x) / Left (-x).
- Y is Forward (+y) / Backward (-y).
- Z is Up (+z) / Down (-z).
- Position a free joint body at Z > 0.1 so it does not start inside the ground plane.

CRITICAL MODEL GENERATION GOTCHAS:
1. CAPSULE GEOM SPAN RULE: Capsule geoms MUST specify either `fromto: [x1, y1, z1, x2, y2, z2]` (endpoint span vector in local space) OR a 2-element size array `size: [radius, half_height]`. NEVER output a single-element `size: [radius]` for a capsule without `fromto`. The compiler falls back to half_height = radius, so the intended rod, spoke or arm collapses into a short pill at the geom's `pos`, and several such geoms at the default `pos: [0,0,0]` stack into one blob at the body's origin.
2. PIVOT COLLISION FILTERING: Visual rods, hub rings, bearings, and axle pins mounted near a shared joint origin MUST set `contype: 0` and `conaffinity: 0`. Overlapping pivot geoms that collide jam the joint and make it wobble in place instead of swinging.
3. HINGE AXIS SPECIFICATION: Every `hinge` joint MUST explicitly specify its rotation axis, e.g. `axis: [0, 1, 0]` for Y-axis rotation.
4. PRESERVE GEOM SPANS ON MUTATION: When proposing scene modifications or re-orienting bodies, NEVER drop `fromto`, `contype: 0`, `conaffinity: 0`, or joint `axis` properties from existing capsule geoms.
5. SCAD BODIES OWN ALL THEIR GEOMETRY. DELETE LEFTOVER PRIMITIVES: A body with a `scad` script compiles into exactly ONE mesh geom that is the whole part. When you convert a primitive-built body to SCAD (or rewrite its SCAD), you MUST also rewrite its `geoms` array down to that single mesh geom. Leftover primitives still render and still collide, layered on top of the mesh, and unpositioned ones pile up at the body's centre. Do not keep primitives "as a collision hull": a dynamic mesh already collides via its convex hull. The only primitive that may share a body with a SCAD mesh is a collision proxy, and it MUST be explicitly positioned AND set `contype: 0`/`conaffinity: 0` on whichever geom should not collide.
6. RGBA ALPHA IS NOT TRANSPARENCY: The renderer draws every geom fully opaque regardless of the 4th `rgba` value. `rgba: [r, g, b, 0.3]` on a "guide" or "bounds" primitive renders as a solid shape occluding whatever it overlaps. To hide a geom, delete it; do not dim it.
7. OPENSCAD TOP-LEVEL PARAMETERS: When generating OpenSCAD code, ALWAYS declare design variables (e.g. `wave_length = 50; // [10:5:200]`, `thickness = 2.0; // [0.5:0.5:10]`) on separate lines at the VERY TOP of the SCAD script, outside any `scale()`, `module`, or block definitions. Include OpenSCAD Customizer range comments `// [min:step:max]`; the app parses them into sliders.
8. HAND-AUTHORED MESH WINDING: A `mesh` geom carries `vertices: [x0,y0,z0, ...]` (Three.js Y-up) and `faces: [i0,j0,k0, ...]`. Every triangle MUST be wound counter-clockwise seen from OUTSIDE the solid, so that (v1-v0)x(v2-v0) points away from the interior. Geoms are drawn single-sided, so a backwards triangle is not drawn at all: a surface built backwards does not look like an error, it looks like the body has gone half transparent and you are seeing its far inside wall through the front. Do not write face indices in ascending order and hope; derive each triangle's order from the outward direction of the face it belongs to. Prefer a `scad` script, which cannot get this wrong.
9. A MESH IS WEIGHED BY WHAT IT ENCLOSES, AND ONLY IF IT IS CLOSED: a watertight, outward-wound mesh gets the mass of its real volume. Anything else falls back to MuJoCo's default, which is the mass and inertia of its CONVEX HULL. For a shape that mostly encloses air — a tree, a chair, an open frame — the hull can be a hundred times the volume, with a centre of mass floating in the gap between the parts, and the body then behaves like a top-heavy block of water rather than like the thing it depicts. Set `density` for what it is made of, and keep the mesh closed.
9a. HOLLOW SHAPES COLLIDE AS HOLLOW SHAPES — BUILD THE SHAPE, NOT A PROXY: MuJoCo itself collides a mesh as its CONVEX HULL, so a cup, bowl, open-top box, funnel or housing would be solid to contact and anything dropped in would rest on an invisible lid at the rim. The app now measures a body's SOLIDITY (true volume over hull volume) and breaks anything below ~0.92 into convex pieces automatically, for every kind of mesh body — imported STL, sculpt, lattice, relief, SCAD, boolean. So model the container as a container. Do NOT assemble a floor plus wall primitives as a collision proxy; that was the old workaround and it is now both unnecessary and worse. Override per body with `collision`: 'hull' to force the old filled-in behaviour, 'decompose' to force the split. One consequence to know: a decomposed hollow body weighs its true volume rather than its hull's, which is often a third as much — set `mass` if you wanted the heavier figure.
9b. HOLES THROUGH A SCULPT, AND PIECES CUT OFF ONE: use physics_sculpt_cut, not physics_cut. It sweeps a polygon (body frame, metres) straight through the body and takes it out, or keeps only the inside with mode 'keep', and the body stays a sculpt you can go on brushing. physics_cut on a sculpt turns it into a boolean and ends sculpting. cap:false leaves the hole open, making the sculpt a shell that will not print; leave it at the default unless the user asks for an open cut. A cut that splits the clay makes one body per piece (listed in `bodies`); delete the unwanted ones with physics_delete_object. physics_undo_sculpt takes back a cut that did not split, like a stroke.
9c. ROUNDED AND BEVELLED EDGES: when the user wants a part to look finished, softer, less boxy, or asks for fillets or chamfers, use physics_round_edges (edges 'all' | 'top' | 'bottom' | 'vertical' | ids, sizeMm, mode 'round' | 'bevel'). Call physics_get_edges first when only particular edges should change; it lists ids, which group each edge is in and the largest size that fits. A size of 5-10% of the part's smallest dimension usually looks right. The rounding is part of the body's boolean, so it collides, prints and machines as rounded. For a 3D-printed part, bevel the bottom edges (0.5 mm) rather than rounding them — a rounded bottom edge overhangs. Sculpt and raw-OpenSCAD bodies cannot be rounded this way.
10. MAKING SCENERY MOVABLE TURNS ITS COLLISION BACK ON: a body authored `contype: 0`/`conaffinity: 0` throughout cannot touch anything, which is right while it is welded in place and useless once it has a joint — it would only accelerate through the floor. Giving such a body its first joint clears those flags. A body that already has one colliding geom is left alone, as is anything that ships jointed and ghosted.

### Example 3: Parametric 2D Extruded Sine Wave via OpenSCAD (50mm long, 30mm tall, 2mm deep)
```json
{
  "nodes": [
    {
      "id": "sine_wave_body",
      "name": "Parametric Sine Wave",
      "type": "body",
      "pos": [0, 0, 0.05],
      "joints": [],
      "scad": "// OpenSCAD Parametric Sine Wave Parameters\nwave_length = 50; // [10:5:200]\nwave_amplitude = 15; // [5:1:50]\nthickness = 2.0; // [0.5:0.5:10]\nextrusion_depth = 2.0; // [0.5:0.5:10]\n\nscale([0.001, 0.001, 0.001]) {\n  linear_extrude(height = extrusion_depth, center = true) {\n    points_top = [ for (x = [0 : 0.5 : wave_length]) [x, wave_amplitude * sin(360 * x / wave_length) + thickness/2] ];\n    points_bot = [ for (x = [wave_length : -0.5 : 0]) [x, wave_amplitude * sin(360 * x / wave_length) - thickness/2] ];\n    polygon(concat(points_top, points_bot));\n  }\n}",
      "children": []
    }
  ]
}
```
